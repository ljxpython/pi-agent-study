# 技术文章生成技能 (Article Generator)

## 一、 技能定位

从面试准备内容 → 高质量技术文章的转化流水线。

**一鱼三吃逻辑**：
```
面试题学习 → 沉淀到 01-interview-qa/
                ↓（选题：有深度 + 有项目实战的题）
           → 扩写成技术文章 → 03-articles/草稿/
                ↓
           → 发布到各平台（掘金 / 公众号 / CSDN / 小红书）
                ↓
           → 精华内容整理到 knowledge-site
```

| 类型 | 说明 | 发布平台建议 |
|------|------|-------------|

## 三、 博客文章结构与生成规范 (Blog Generation Specification)

### 1. 文章脉络原则：因题施策，自由舒展（拒绝死板套路）

**严禁把章节结构写成僵化的“十殿阎王”式固定八股文！** 每一篇技术长文的具体脉络、小节划分与推导逻辑，必须**根据具体选题和真实工程场景自由灵活裁定**：
- **故障排查类**：现场还原 ➔ 链路追踪 ➔ 根因下钻 ➔ 防御加固；
- **架构剖析类**：设计动机 ➔ 关键权衡 ➔ 核心模块解密 ➔ 生产实践；
- **源码拆解类**：最小样板 ➔ 核心抽象 ➔ 关键时序单步调试 ➔ 避坑指南；
- **选型对比类**：对比维度 ➔ 方案矩阵 ➔ 生产基准评测 ➔ 决策建议。

无论采用何种叙事脉络，**以下三个底层底线必须无条件坚守**：
1. **开篇即入戏**：第一句话必须直接切入真实痛点、现场报错或具体代码瓶颈，严禁任何宏大虚浮的时代开场白；
2. **收尾求务实**：收尾只保留硬核落地建议、真实局限性或开放讨论，坚决杜绝小学作文式升华鸡汤；
3. **真实代码依托**：涉及实战必须结合真实项目（如 `ai-agent-platform`）落地代码与踩坑经验，杜绝凭空泛泛而谈。

### 2. 文字编写守则（强制去 AI 油腻感 · 遵守 humanizer-zh 规范）

所有生成的博客长文，**默认强制执行全局 [humanizer-zh](file:///Users/lijiaxin/.gemini/config/skills/humanizer-zh/SKILL.md) 规则**：
1. **❌ 严禁宏大时代开场**：杜绝“在当今AI浪潮席卷”、“随着大模型突飞猛进”，第一句直接说报错和代码；
2. **❌ 严禁鸡汤升华收尾**：杜绝“让我们拭目以待”、“道阻且长，行则将至”，收尾只保留硬核总结与局限性；
3. **❌ 严禁堆砌无主语黑话**：杜绝“降本增效、赋能业务、打破壁垒”，落实到类名、函数名与量化指标；
4. **❌ 严禁 Not-X-but-Y 排比反差**：杜绝“它不仅是一个工具，更是...”，直接说核心机制；
5. **✅ 真实工程师口吻**：保留老练、务实、直击要害的技术表达。

### 5. 中文生图字形防翻车铁律 (Anti-Typo & Typography Defense)

大模型在生成中文图像时，生僻复杂汉字极易产生形近字形变与笔画粘连。为保证出图 100% 零错别字，生图提示词必须恪守以下四条铁律：
1. **高频高容错字原则**：
   - ❌ 避免使用易形变生僻字：如“立宪”（易变形为立志）、“踩坑”（易变形为踩坊）、“向量”（易变形为向重）、“篡改”（笔画粘连）；
   - ✅ 优先选用笔画清晰、结构稳固、高频常用汉字：如用“确立规则”替代“立宪定规”，用“实战打磨”替代“踩坑踩出”，用“结构化文件”替代“复杂向量库”，用“修改”替代“篡改”；
2. **气泡框文案极度克制**：
   - 小机器人气泡框文案必须控制在 **≤ 15 字**，字大句短，严禁塞入长句导致大模型字符挤压变形；
3. **文本必须用反引号包裹**：
   - 画面中所有需要绘制的文字必须用反引号（`` ` ``）严格包裹，让模型明确文字与描述指令的边界；
4. **提示词显式注入防呆负向约束**：
   - 提示词末尾必须包含：`CONSTRAINTS: 100% correct simplified Chinese text, standard Chinese characters, zero typo, clean typography, pristine flat paper. STRICT NEGATIVE: NO stray rings, NO grey smudges, NO English gibberish, NO messy garbled letters, NO 3D metallic textures, NO dark cyberpunk backgrounds, NO blur, NO distorted robot anatomy.`

## 四、 文章生产执行工作流

```
Step 1：选题与立意
  → 从 01-interview-qa/ 筛选高价值工程痛点，或结合 ai-agent-platform 真实功能立项
  → 拟定爆款工程标题（25~35字）与核心导读

Step 2：大纲规划与配图心流设计
  → 规划各章节技术点，以每 2~3 节为单位划分视觉休息节点
  → 明确规划全篇 4~5 张核心图元清单（Banner、架构拓扑、执行小结卡、进阶机制卡、万能公式卡）

Step 3：内容深度撰写（执行 humanizer-zh 规范）
  → 真实代码、数据结构、负向禁令清单
  → 结合 ai-agent-platform 开源实现，提供差异化核心壁垒
  → 彻底剔除所有 AI 腔调与空洞套话

Step 4：Style 12 系列卡片生成与字形自查
  → 调用 gpt-image-gen 批量生成横版 16:9（1536x864）卡片
  → 严格执行字形防翻车铁律（高频字、气泡≤15字）
  → 产出后必须调用 view_file 放大核对每一个汉字，发现错别字立即重新精修

Step 5：草稿存档与全渠道同步
  → 通用底稿存入 03-articles/drafts/YYYY-MM-DD-[slug].md
  → 更新 03-articles/README.md 进度表
  → 触发 article-publisher / WechatSync 一键直推掘金、知乎、CSDN 等草稿箱
```
