# 02-labs 实操实验沙盒

## 目录职能说明

**学框架不敲代码、不看真实日志、不造报错就是耍流氓！**  
这里是你的代码练手操练场，与外部项目环境彻底隔离。

- `playground/`：随手测试代码、临时脚本验证、一次性探索 Demo。
- `milestones/`：按章节/里程碑组织的正式实践工程。

---

## 🏛️ 三层角色隔离与渐进式里程碑规范

为杜绝“把演示业务当成框架主角”以及“单文件反复覆盖抹杀认知演进”的问题，`02-labs/milestones/` 遵循以下两大铁律：

### 1. 三层角色物理隔离规范 (Three-Tier Sandbox Structure)

每个章节的复杂实验工程，按角色清晰拆分目录：

```text
02-labs/milestones/<chapter-name>/
├── 1-runtime/          # 智能体/框架宿主环境 (主控进程、CLI、状态图入口、启动脚本)
├── 2-harness/          # 挂载的外挂装备 (自定义工具、中间件配置、存储适配器、Prompt模板)
└── 3-target/           # 演示靶场载体 (故意写挂的代码、被操作的数据 —— 纯属测试靶子！)
```

### 2. 渐进式切片演进铁律 (Progressive Slicing Rule)

对于代码实现类章节，**严禁在同一个文件上反复修改覆盖**，强制拆解为带编号的独立渐进式文件：

```text
02-labs/milestones/<chapter-name>/
├── 01-minimal-bootstrap.ts    # 阶段 1：剥离一切外挂的最简启动
├── 02-middleware-injected.ts  # 阶段 2：引入核心中间件与工具调用
├── 03-persistence-added.ts    # 阶段 3：挂载持久化与状态恢复
├── 04-fault-injection.ts      # 阶段 4：主动注入网络超时/格式异常，观察框架自愈
└── run-demo.sh                # 统一启动入口 (支持 ./run-demo.sh 01, ./run-demo.sh 02)
```

- **增量注释要求**：每个演进脚本顶部，必须明确写出【本阶段认知跃迁与上一阶段的增量对比】；
- **回溯自由**：学习者随时可以一键运行任何历史阶段的代码，看清架构是如何从 0 演进到 1 的。
