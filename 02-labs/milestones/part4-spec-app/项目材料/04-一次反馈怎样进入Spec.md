# 一次反馈怎样进入 Spec：从拖工具卡到只选资料

这张早期**生成示意图**把“查询工单”和“保存报告”画成了左栏能力卡，需要用户先把能力拖到输入框。它用于讨论流程，不是运行截图；图中的连接状态也不能证明后端已接通。

![早期生成示意：左栏有查询与保存能力卡，查询能力被拖向输入框](./Images/04-需求反馈-早期拖入查询示意.png)

项目反馈指出，用户只是选择工单资料并提问，不必先理解或拖动内部工具。团队据此把左栏改为资料入口，让查询工具由后端按本轮任务受控调用。当时前端 Spec 的“选择资料”条目（2026-09-21 的界面阶段合同）写明：“左栏不展示Tools或Skills，不存在工具选择标签与工具拖拽。”同一条还要求资料加入输入框与发送问题分开操作。现在的应用是否照此执行，要用当前页面和请求结果检查；这段历史 Spec 摘录不代替当前源码。

| 材料 | 它回答的问题 | 不能据此下的结论 |

把这次变化写成自己的开发任务：**当用户选中一份资料并提问，页面无需展示内部工具卡，仍应返回当前资料的记录与来源；若本轮没有正确绑定资料，不能沿用上次结果。**实现后分别检查界面、后端本轮资料和工具结果。只改页面、却让工具读旧资料，仍没有完成这条需求。

材料出处：项目《决策过程图集》的最初流程草图与反馈阶段，以及 2026-09-21 前端 `frontend-spec.md` 的“选择资料”历史条目。原图按字节保留于本课材料；这是一段真实设计决策的教学摘录，不是完整 Spec，也不代替教师发放版本的现行工程合同。
