# 工单问答助手｜项目过程阅读入口

这里是随课项目的**学员阅读副本**，用于从需求、输入、设计、开发到验收和复盘追踪一条项目链。运行入口在另一个交付文件夹的[学员版源码](../../Pi工单问答助手-学员版/README.md)；课堂练习按讲师展示的课件执行。

建议依次阅读：

1. [需求范围](./01-目标与需求/需求范围.md)：产品目标、范围变化及前端阶段取舍。
2. [资料与来源](./02-资料与输入/来源.md)及[八阶段决策过程图集](./02-资料与输入/决策过程图集/00-阶段索引.md)：从最初流程草图、用户反馈、否决稿到最终视觉基线，按图追踪功能与界面的取舍。原项目现存的 39 张图片均在 `02-资料与输入/` 中。
3. [前端 Spec](./03-方案与设计/frontend-spec.md)和[后端 Spec](./03-方案与设计/backend-spec.md)：两端职责与阶段验收。前端另附[阶段 08 实施前快照](./03-方案与设计/frontend-spec-v1.8-阶段08实施前快照.md)，帮助区分批准设计与后续实现。
4. [阶段计划](./04-执行过程/PLAN.md)、[审核与协作记录](./04-执行过程/审核与协作记录.md)及[项目阶段状态](./04-执行过程/PROJECT_STATE.md)：从前端演示到 SDK、业务工具、确认与恢复的推进过程；另保留两份早期设计审查 BLOCK 记录 `design-sol.md` 与 `design-sol-r2.md`。这些是各自日期的过程记录，不能把历史状态当作当前运行结论。
5. [验收摘要](./06-验收与交付/验收摘要-学员版.md)：历史工程证据能说明什么、不能说明什么。
6. [前端决策复盘](./90-复盘与追溯/01-给学员的前端项目决策复盘.md)及[项目复盘](./90-复盘与追溯/00-项目复盘-学员版.md)：把反馈、边界与失败变成下一次项目的检查方法。

需求、两份 Spec、阶段快照、PLAN、决策图集、视觉基线、审核记录和前端复盘取自原项目，保留阶段叙述；分发副本只调整了少量本机链接与内部验收引用。来源、验收摘要、项目复盘和本入口按学员阅读目的重新整理。原项目及其测试档案保留原位；机器派发回执、测试脚本和原始日志没有作为学员材料复制。

**状态边界：** 文档记录的是工程不同日期的决策与验证；随课源码的实际运行以它自己的 README、你当前的模型配置和你亲自看到的结果为准。历史测试通过不等于学员环境、真实模型业务或课堂教学已通过。
