# 阶段 08｜工作台边框与对话布局

本阶段记录 2026-09-23 的视觉讨论，供学员按“实际问题 → 单项候选 → 用户反馈 → 合成基准 → 可验收 Spec”阅读。图片均按原字节保存；这是一段**设计决策过程**，不代表新版前端已经实现。

## 起点：真实页面暴露了什么

用户提供的[修改前页面](00-修改前实际页面.png)显示：工作台贴近视口上下边缘，底部缺少完整收边；用户和助手消息都是居中的大矩形，角色方向不清楚。用户先要求分别看外框与左右交替消息两种效果，确认后再合成。截图是当时的实际页面；其中工单内容、连接提示和资料状态不用于定义后续测试预期。

## 决定怎样进入开发合同

本阶段没有直接改前端源码。用户先要求修改 Spec，再按 Spec 开发与测试。实施前冻结的[前端 Spec v1.8 快照](../../../03-方案与设计/frontend-spec-v1.8-阶段08实施前快照.md)保留原字节，SHA256 为 `472f91635031259af689e207789bf6105e31867257ba712b888ba0b0f46eca78`；快照与现行 Spec 同目录，原有相对引用仍可打开。**它是本阶段记录，不是后续永远有效的执行入口**。实际开发应读取[现行前端 Spec](../../../03-方案与设计/frontend-spec.md)的 AC25—AC30B 与 §十六，并先核对当前源码和约束是否漂移。

从反馈到验收的对应关系：外框和底边进入 AC25；消息带与输入框共宽进入 AC26；左右归属和长文本进入 AC27；助手 Pi 标识进入 AC28；输入区提示与拖放/键盘保护进入 AC29；浏览器回归与 HTTP/SSE 烟测进入 AC30A/B。Spec 已规定测量口径、正反例、唯一写入者和证据目录。`SPEC_READY_FOR_EXECUTION`只表示文档可用于开工；图片批准与 Spec 审核均不等于代码和浏览器验收通过。

## 学员练习

只看[修改前页面](00-修改前实际页面.png)与[最终合成图](05-合成视觉基准.png)，写一张自己的变更卡：列出三个要改的可见行为、一个容易被漂亮图片掩盖的失败场景、每项在浏览器里怎么量或观察。再对照 Spec 的 AC25—AC30B：若答案只写“更好看”而没有消息方向、输入对齐或底边可见的判据，就还不能交给开发者执行。
