# 大型项目防返工开工范式

> 实证来源：FF-CompanyBrain 企业 RAG 中台（三链路 + 平台层，2026-06-29 ~ 07-10，单人 + 多 AI agent 协作）。
> 与 [[PKP生产Spec-项目双产出工作流]] 互补：PKP 管"吃透项目→产教学资产"，本篇管"改造项目→防止返工"。
> v2：经 Codex 异源两轮对辩收敛——三原理置顶、三源改四源、六件套改七件套 + AI 协作门控独立成层、业界范式正名。

## 〇、数据结论（为什么值得前置投入）

- 44 个 P 编号 spec 中，**返工修复/后置补课类 ≥14 个（约 1/3）**；纯新功能仅约 8 个
- 台账约 90 个实际问题里，**约 45% 属 A 档**（开工前几份文档即可消除）、35% 属 B 档（需 lint/CI/清单机制）、**仅 20% 本质不可前置**
- 最强挫败信号不是"需求变了"，而是"**AI 声称完成但实测失败**"；纪律演化主线 = 口头纪律 → 文档契约 → 机制门控，新项目应直接从第三级起步
- ROI 限定：以上比例来自本项目实证，前置投入的合理规模随项目风险档位裁剪（见 §六），不外推为"所有项目都应投入同等前置成本"

## 一、三条第一性原理（范式的根，文档只是载体）

> 本范式不以"写几份文档"为目标，只遵守三条原则。七件套是平台型项目对这三条的一种实现；非平台项目可删减、合并或替换载体，只要三条原则仍被满足。

1. **高代价隐式假设必须显式化，并尽可能转成可执行约束**——载体优先级：schema/类型/测试/门控 > 人读文档 > 口头共识
2. **错误必须在最接近引入点的位置、以直接证据尽早暴露**——可迁移的度量是**反馈回路半径**：从错误引入到第一个可信信号，中间跨了多少模块/会话/天数，越短越好
3. **每次变更必须携带影响面、迁移/回滚方案和回归证据**——变更不是改那一行，是改那一行 + 它波及的代码/数据/配置/测试/文档/其他 agent 的工作成果

## 二、返工四源（先诊断，再开药）

> 先区分两种返工：**学习性返工**（新证据推翻旧假设——必要且健康，如实测后换 reranker）vs **失控性返工**（本可通过低成本试验、影响分析或机械门控避免的重复修改）。本范式只消灭后者。

### 1. 意图未决（目标/边界/取舍没形成可执行决策）
- [ ] 项目定位档位（demo / 内部工具 / 企业级上线）第一天写死了吗？——"要真上线的企业级产品"第 5 天才拍板 → P12 影子后端下沉大手术
- [ ] 关键选型做过"最迟决策点"登记吗？——embedding 三换（4096→1024→1536→v4 1024），每换一次 = 重灌数据 + 清僵尸表 + 改课件三重连锁
- [ ] 各子系统的产品定位（谁用/什么场景）开工就答了吗？——三链路"个人/团队/公司"定位第 10 天才讨论

### 2. 契约不明（术语/接口/状态/不变量/所有权含混）
- [ ] 实体唯一性契约（一场景一 source 还是一文件一 source？重复提交幂等还是报错？）——同一 409 静默丢文件 bug 三引擎各爆一次（I74/I84/I87），修复又引入归因错乱 I95
- [ ] 核心参数语义 = 用户心智模型？——TopK 被做成"每源"语义，五个子批接线建立在错误语义上，用户一句"500 个源难道返回 500 条？"推倒重来（I60）
- [ ] 失败可见性有约定？——静默失败是脏数据之母：0 chunk 标 ready（I64）、分类器失败默认跳过检索（I37）、批量 catch-continue（I87）

### 3. 反馈迟滞（错误离引入点太远才暴露）
- [ ] spec 内承诺有闭合追踪？——P3 承诺"逐个 to_thread"只做 2 条，P15 复扫出 ~26 处 async 假壳（详见 [[FastAPI同步栈异步隔离工程实践-20260707]]）
- [ ] 分层架构逐层接线核过？——"组件→route→store→模块"四层，每层都是可静默漏接的断点；P22/P25/P26/P31 全是"后端能力齐、UI 不可达"补课
- [ ] 批量/并发路径测过？——单文件/串行通过 ≠ 多文件/并发通过；"批量恰好卡 1 篇"同款 bug 三次复发（I82/I92/I105）

### 4. 变更失控（改动后未识别影响面，波及未被管理）
- [ ] 修复改变数据形态时 grep 过下游隐含假设消费点吗？——I87 幂等修复打破 refBySource"一 source 一 document"假设 → I95 来源全标错
- [ ] 删除有 SOP 吗？——数据清理三度误伤（I94/I97/I101/I131），每次清理都在制造下一次的脏数据
- [ ] 换供应商/换模型的迁移与清障是变更方案的一部分吗？——维度僵尸被踩 3 次（I66/I73/I120）

### 剩余 ~20% 本质不可前置（不要为它们写前期文档）
检索相关性体感 / 第三方库内部行为（LightRAG 去重 hash、pipeline 锁）/ provider 抖动 / UI 审美——正解不是"想更多"，而是把发现成本降下来（§三之 7 快速暴露基建）。

## 三、开工前置七件套（平台型项目的实现载体）

> 每件标注【最小可用形态】与【升级条件】——"半天启动"是可验证承诺，不是姿态。

### 1. 决策与假设卡（原"立项决策卡+选型冻结"，正名：项目章程 + 轻量 ADR + 假设清单）
- [ ] 一句话 whole task（能端到端跑的真实任务）+ 受众 + 验收
- [ ] **定位档位三选一写死**：demo / 内部工具 / 企业级。企业级 = 真鉴权 + 真存储 + 并发治理 + 审计从第一天算工作量
- [ ] **跑通证据**：最薄一条真实链路贯穿全栈并留日志（brownfield=先跑通现状；greenfield=即 walking skeleton / tracer bullet）
- [ ] **已决事项**：决策 / 理由 / 适用范围 / 日期，并标注 one-way door（不可逆：存储形态、embedding 维度）还是 two-way door（可逆：UI 布局、阈值）
- [ ] **待证假设**：验证方法 + **最迟验证点** + 失败后替代路线——第一次选择先做低成本验证，别让"学习"以全量重灌的价格发生
- [ ] **变更协议**：什么新证据出现必须重开决策 + 影响面/迁移/回滚成本清单。核心一句话：**不是不许换，是换之前必须看见代价**
- 【最小可用形态】一页：whole task + 档位 + 3 个 one-way door 决策 + 3 条待证假设。【升级条件】决策 ≥10 条时拆独立 ADR 目录

### 2. 语义契约页（正名：ubiquitous language + contract-first 的轻量版）
- [ ] 核心名词的用户心智模型：TopK 全局还是每源？"一个知识源"对应什么实体？重复提交幂等还是报错？
- [ ] **数据流矩阵**：每类输入（文本/PDF/CSV/图片）进哪张表 × 每个读路径（问答/检索/统计）查哪张表——"CSV 写 tables 而 QA 只查 chunks、数值静默答错"（I83）可在纸面静态推出
- [ ] **状态机**：合法状态迁移写全（uploaded→processing→ready/failed），状态判定以权威状态为准、禁依赖协程返回（I105 根治点）
- [ ] **所有权**：每类实体/状态字段的权威写入方是谁（I95 的下游假设错乱即所有权不明）
- [ ] **持久化不变量**：如"ready ⇒ 至少一个可检索产物"（直接封死 I64 类静默假成功）
- [ ] 契约尽可能落为 schema/类型/契约测试（可执行 > 人读）；人读文档是底线不是目标
- 【最小可用形态】名词表 + 数据流矩阵 + 1 张状态机图。【升级条件】跨语言/跨模块 ≥3 方消费同一契约时，加消费方驱动的契约测试

### 3. 假实边界台账（mock ledger）
- [ ] 凡 mock/fixture/写死占位，**写下的当刻登记**：位置 → 真实消费点 → **截止阶段** → 到期未接真自动升级为阻断项
- [ ] 规则一句话：**允许 mock，禁止不登记的 mock**
- [ ] 载体可嵌入各功能 spec 的"替身声明"节，但必须**机器可扫描**（统一标记词，grep 可汇总全局清单）
- 实证：I42 全量确账（18 个假参数）就是本文档的事后补做版；若 M0 就有，I39/I62/I124 全部从"用户实测发现的假 UI"变成"已知边界"
- 【最小可用形态】统一注释标记 + 一条 grep 汇总命令。【升级条件】mock ≥15 处时上 lint/CI 扫描

### 4. 失败可见性公约（正名：fail-fast / andon 思想的项目化）
- [ ] 0 产出不得标 ready
- [ ] 批量部分失败必须上抛 UI
- [ ] 任何 fallback 必须显式 surface + 留日志
- [ ] **每类失败逐个定义 fail-open 还是 fail-closed**（检索路由失败→保守多检索；rerank 失败→fail-open 保留全部；鉴权失败→永远 fail-closed）——不设"统一保守"的一刀切
- 【最小可用形态】上述 4 条进仓库 CLAUDE.md/AGENTS.md 当红线。【升级条件】企业级档位补错误分级、trace ID、SLO/error budget

### 5. 配置消费点清单（正名：12-factor config + 消费点追踪增量）
- [ ] 每个 env 变量登记：消费点 → 默认值 → 生效条件（重启/热载）——"改个端口、前端从此永远落 mock"（I12→I23）即消费点无单一真相源
- [ ] **最低核心门控**（Codex 坚持项，采纳）：启动时报告未知/未消费配置键 + 关键配置打印最终解析值与来源层（DB 覆盖/env/默认）——AI 极易生成"语法正确、系统未消费"的幽灵配置，自动校验近零维护成本
- [ ] CONFIG 与 SECRET 分离：数值配置可进 DB 分层覆盖；密钥永远只在 .env/KMS，UI 只暴露脱敏指纹 + 测试连接（决策考古 D4）
- 【最小可用形态】.env.example 逐行注释消费点 + 启动期未知键告警。【升级条件】企业级档位补 schema 校验、配置版本审计

### 6. DoR + DoD（正名：Definition of Ready / Done，分三层）
**DoR（开工闸，五问）**——很多返工发生在"需求尚不可执行就让 agent 开工"：
- [ ] 验收样例存在吗？权威契约定了吗？外部依赖可用或有登记的替身吗？未决问题低于开工阈值吗？失败路径和非目标写清了吗？

**DoD（完工闸，三层）**：
- **全局基线**（跨项目通用）：真实测试过含失败路径 / 批量与并发路径 / 涉及的文档与契约镜像已同步 / 破坏性操作有二次确认
- **项目 profile**（本项目形态特有，迁移时重写这层）：三层接线可达（组件→route→store→模块，UI 真点得到）/ 权限口径与既有路径对齐 / 删除有级联清理（I94/I131 复发两次）/ 参数旋钮三证（页面可改 + DB 落库 + 行为真变化）
- **功能增量**（该功能 spec 里的专属验收项）
- 【最小可用形态】全局基线 8 条 checklist。【升级条件】项目 profile 随第一个功能的返工教训生长

### 7. 快速暴露基建（四套机制的合集，对付 ~20% 不可前置；第一个功能之前立起来）
- [ ] **评测标尺先行**（回归评测）：黄金集 + harness——改前基线改后对比；负结果也是价值（I70 靠它拦下"照搬 best practice 的伪升级"）
- [ ] **问题台账制度**（缺陷管理）：7 字段修复模板 + 证据色标 + "未填全不得声称已修复"红线——本项目问题快速定位的最大功臣
- [ ] **真跑门控**（验收门控）：底层表述——**每个验收声明必须绑定可重复获取的直接证据；代理指标只有在与目标结果的相关性已被验证时才可作门控**。项目化示例：产物计数==输入数、psql 双证、渲染后人眼（人眼是必要环节但不是机械门控，二者分开记）
- [ ] **数据生命周期协议**（测试数据治理）：测试数据前缀命名（stress-/p24-）+ 评测语料保护名单 + 删除 SOP（平台侧 first、容忍后端 404）
- 【最小可用形态】20 条黄金集 + 台账模板 + 前缀命名约定，半天内可全部立起。【升级条件】进 CI 变 fitness function（架构约束自动验证，如"禁止前端直连引擎"）

## 四、AI Agent 协作门控（单人 + 多 AI 形态的独立治理层）

> 传统团队靠会议和 code review 形成共享认知；AI 协作的六大特有风险必须用机制补位——这是本范式相对业界成熟 pattern 的最大原创层。

- [ ] **完成声明四元组**：主张 / 直接证据 / 覆盖范围 / **未验证项**——禁止只报"已完成"；无证据的主张自动降级为待验证
- [ ] **会话交接契约**：跨会话必须更新——当前事实快照 / 活跃决策 / 已知失败模式 / 未决问题 / 禁止事项 / 下一步（对应 /handoff + "新会话先跑核验命令确认地面真相"协议）
- [ ] **影响面前置**：每次非局部修改前先列——根因假设 / 受影响的调用者·数据·配置·测试·文档 / 回归清单 / 回滚方式（直接执行原理三）
- [ ] **唯一事实源**：契约与决策卡是多 agent 共同的真相源；发现冲突先修订事实源再继续实现；契约修改后明确哪些 agent 产出作废
- [ ] **异源审核制度化**：高风险改动至少一次异厂商模型独立审；实现者只交目标/diff/契约/证据，不得递诱导性结论；审查建议采纳前反向三验（事实可验/与既有约束一致/代价评估）——审查不能替代真实执行
- [ ] **区分验证剧场**：实现者自写测试不得单独作为验收依据；至少保留一层独立证伪能力（契约测试 / 黄金集 / 端到端真跑）——测试是否存在不重要，是否有独立证伪能力才重要

## 五、业界范式对照表（正名，防重新发明轮子）

| 七件套 | 对应成熟 pattern | 本范式的真实增量 |
|---|---|---|
| 决策与假设卡 | ADR、Design Doc/RFC、pre-mortem、one-way/two-way door | 变更连锁成本前置可见 |
| 语义契约页 | DDD ubiquitous language、contract-first | 用户心智模型对齐 + 跨存储数据流矩阵 |
| 假实边界台账 | test doubles、tech-debt register、DoR | 针对 AI 批量产假实现的登记纪律 |
| 失败可见性公约 | fail-fast、Toyota andon、SRE 错误处理 | 逐类 fail-open/closed 裁决表 |
| 配置消费点清单 | 12-factor config | 消费点 + 生效条件 + 幽灵配置门控 |
| DoR + DoD | Scrum DoR/DoD、quality gates | **证据型 DoD**（适配 AI 声明不可信） |
| 快速暴露基建 | walking skeleton、golden master、CI 门控、fitness functions | 评测先行拦伪升级 + 台账证据制度 |
| AI 协作门控 | （业界尚无成熟对应物） | **本范式最大原创增量** |

## 六、时序与裁剪（迁移到新项目）

| 时点 | 动作 |
|---|---|
| M0（时间盒 ≤4h） | 七件套之 1 + 2（决策与假设卡 + 语义契约页），过 Exit 闸才动工 |
| 第一个功能前 | 七件套之 7（评测标尺 + 台账 + 真跑门控 + 数据协议）+ AI 协作门控立起来 |
| 全程随写随登 | 七件套之 3 + 4 + 5（mock 台账 / 失败公约 / 配置清单） |
| 每个功能开工/收尾 | 七件套之 6（DoR 五问开工，DoD 三层收尾）|

**按风险档位裁剪**：
- demo：只留 1（半页）+ 3 + 完成声明四元组
- 内部工具：再加 2、6 全局基线、7 之台账与真跑门控
- 企业级：全套 + 各件的"升级条件"逐步启用
- **裁剪必须留痕**：跳过了哪件 / 对应风险 / 补做触发器 / 最迟复核点——防"按风险裁剪"退化为随意省略

## 七、边界提醒（防范式自身官僚化）

- [ ] **文档准入原则**：每份文档必须能指出它消灭哪个具名风险，否则不写
- [ ] **不要试图前期想清一切**：UI 视觉/交互手感/三方库内部行为/真实 query 体感留给迭代——为它们写前期设计文档是负 ROI。范式目标不是零返工，是把发现成本从"用户直播前实测撞见"降到"门控自动报警"，并给学习性返工留出合法空间
- [ ] **文档不绑检查点就会腐化**：PKP 同步靠人肉督促约 20 次的教训——七件套每份绑一个机械触发点（mock 台账绑"合并前 grep 汇总比对"；决策卡绑"改 EMBEDDING_* 必先出连锁清单"），否则就是第八份会腐化的文档
- [ ] **M0 超时间盒必须停**：核心两件 >4h 说明范围过大或信息不足，先收窄项目再回来补卡
