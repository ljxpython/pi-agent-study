# 项目开工约定

本目录是第四课第二章的从零开工演示副本，不是已完成的 Pi 工单问答助手工程。以当前用户在本目录给出的决定为准；现有课程案例只能作为讨论素材。

1. 开工先读 `00-项目入口.md` 与 `docs/方法/工程规范.md`；追问需求前，再读 `docs/方法/大型项目防返工开工范式.md` 的第一、二、六节，指出本轮适用的规则、关键未决事项、主要返工风险与裁剪理由。不以“已经读取”代替落实。
2. 需求未确认时先追问会改变范围、权限或验收的问题；不得自行把案例中的假设写成用户决定。
3. 用户明确要求生成需求文档后，才写 `docs/需求/需求.md`；用户确认需求并要求生成设计文档后，才写 `docs/设计/架构决定.md`。每次只更新当前获准的文档和 `00-项目入口.md` 的现行链接。
4. `docs/规格/` 留给后续前端、后端阶段 Spec；未进入对应阶段时不预填。编写 Spec 或实施前，按风险读取 `docs/方法/企业级SPEC驱动开发全周期SOP.md` 的第一、三至五节，并重读入口指向的现行需求、设计和 Spec。局部任务不机械套用完整十二项合同；大型项目也要写明裁剪依据。
5. 本轮课堂只讨论与生成文档，不写应用代码、不调用真实模型或外部服务、不把历史工程的完成状态写进新项目。文档中分开标注已确认、待确认与示例数据；给出能够检查的正常及失败条件。
