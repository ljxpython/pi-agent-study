**首次安装和项目准备从“学员扩展资源包根目录”开始；第五章直接延续第四章的工单项目。** 先在文件管理器找到解压后的资源包文件夹，在这个文件夹打开系统终端。根目录应能看到 `package.json`、`scripts`、`official-examples` 和 `samples`，先核对：


这里不使用讲师电脑的绝对路径，也不依赖资源包安装在桌面还是其他磁盘。后文写“根目录终端”，就是在这个位置打开的系统终端。**第四章完成后直接在同一个工单项目进入第五章；独立 Hooks 样例按第4节操作**；不要在Pi输入框粘贴 `cd` 或 `node`。

本稿新建案例统一命名为 `student-workspaces/ticket-live`，便于后续命令直接复制。如果你已经在测试 `student-workspaces/ticket-某个时间戳`，继续使用原副本，把后文命令中的 `ticket-live`替换成你实际的文件夹名；不要重新创建或覆盖它。可以在根目录用 `ls student-workspaces`查看已有名称。

**第四章提示词可以按下面的顺序使用，前提是准备检查通过。不要再贴到历史C/D实验目录，也不要使用旧tui.mjs运行完整任务。**

| 检查层次 | 本轮结果 | 你接下来测什么 |

## <center>2. 第一次准备：扩展、项目、模型分别检查</center>

### 2.1 安装扩展，只做一次

前提：Pi 0.85.1、Node≥22.19、npm、Python3、Git可用，且你有可用模型。包已安装对应版本时跳过。在根目录系统终端执行；不要在Pi会话里执行：

```bash
pi install npm:pi-memory@0.4.2
pi install npm:pi-mcp-adapter@2.34.0
pi install npm:pi-web-access@0.29.0
pi install npm:@narumitw/pi-lsp@0.49.7
pi install npm:pi-subagents@0.68.0
pi list
```

以上将固定版本登记为用户级扩展。资源包保留相同版本原始tgz和源码供查看、分发；Pi此路线通过npm源解析并安装，仍需要网络，不宣称全离线安装。先检查 `~/.pi/agent/extensions/todo.ts` 和已有登记项；已有Todo就跳过下面命令。只有没有Todo时，才在**学员扩展资源包根目录**登记官方Todo：

```bash
pi install ./official-examples/todo.ts
```

保留该文件原位置，不再复制一份到全局extensions以免重复注册。若已出现 `Tool "todo" conflicts with ...`，且决定保留原全局目录版本，先退出Pi，在资源包根目录执行 `pi remove ./official-examples/todo.ts` 取消新登记项，再回到工单项目启动。不要删除正在使用的全局文件。原有不相关扩展可能产生工具名冲突；出现重复工具报错时通过 `pi config` 检查启用项，不直接改全局配置文件。

### 2.2 创建新工单项目

在根目录终端执行下面的准备命令，显式指定统一的相对目录名：

```bash
node scripts/prepare-ticket-demo.mjs ./student-workspaces/ticket-live
```

脚本创建全新的 `student-workspaces/ticket-live`，安装**工单项目的开发依赖**，准备三份待实现文件、24+3测试、MCP/LSP配置、两个只读角色和两份提示词模板。不重新安装扩展，不复制模型密钥，不重置旧证据。如果目录已经存在，脚本会拒绝覆盖。继续已有练习时跳过准备命令；需要新一轮时另取新名字，并在后续命令中使用相同名字。

准备成功后，仍从资源包根目录执行以下相对路径命令；脚本不会替你切换当前终端目录：

```bash
cd ./student-workspaces/ticket-live
npm run preflight
source ./course-env.sh
pi
```

- 预检应返回依赖可用、政策4/24、工单6条。MCP是Python本地合成服务；没有数据库、联网业务查询或写记录操作。
- 首次启动按Pi提示确认信任当前练习目录；否则项目资源可能不加载。这里只信任你刚检查过的副本。
- 在Pi里用 `/model` 选择已经配置好的模型，先输入“请只回答：模型连接正常。”；401/403或其他错误时停止模型演示，检查模型服务配置，不靠反复换提示词解决。
- 在Pi里输入 `/course-check`，看 `missing` 是否为空、`memoryDir`是否为当前项目的 `.course-memory`、当前模型是否有效；工具登记清单在 `.course-evidence/registration.json`。这一步不调用模型，不证明工具执行成功。
- 若项目MCP未连接，用 `/mcp` 查看；LSP启动诊断用 `/lsp`，实际文件诊断见T2。子角色继承当前模型，模型必须也能供子进程使用。

以后仍然直接 `pi`。`source ./course-env.sh`只把本轮Memory隔离到当前项目，同一终端无需反复执行；换终端或新副本时重新执行。退出本练习后用新终端处理其他项目，避免继承记忆路径。这里不用 `npm run memory`。

### 2.3 准备三个观察位置

- Pi窗口：工具名称、输入、返回和最终回答。
- 文件窗口：`.course-memory/MEMORY.md`、三个实现文件、`.course-memory/daily/`。
- 验证终端：测试、类型检查、最终JSON、`git diff`。不要投屏模型密钥文件。

每轮使用新副本，真实截图记录运行编号。历史截图标记来源，不能当成本轮刚执行的结果。完整流程耗时以你实际彩排为准；课前完成一次全流程，再决定直播现场展开哪些步骤。
