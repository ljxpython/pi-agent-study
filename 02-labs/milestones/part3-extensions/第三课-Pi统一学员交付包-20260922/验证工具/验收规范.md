# Pi扩展验收规范：执行与门禁

摘自课程项目验收规范的执行顺序、硬性矩阵和门禁说明。原始研究记录不作为学员运行依赖。门禁检查证据完整性，不会替你运行Pi或证明全部功能通过。

## 二、执行顺序：step × verify

1. **冻结验收合同**：明确目标、原提示词、预期文件/消息/UI、工作目录和现有上下文。记录 Pi/Node/OS/终端、实际模型及扩展组合。保存代码清单 SHA256；测试前先写必测项，不能测完再挑有利指标。
2. **复现历史缺陷与单元回归**：保留失败证据，测试正常和非法输入、消息失败重试、状态一致性。测试工具不得替用户改正原提示词中的规划结果。
3. **真实原生终端组合运行**：用 tmux/PTY 驱动普通 Pi，不使用 Computer Use。实际界面与真实工具事件、文件、模型身份同时取证；Playwright 仅用于网页，不代替 TUI。
4. **故障与恢复**：按下表注入等待、断流、假进度与取消；每次故障后继续发一条正常提示词，验证能恢复。可测性不足就先补观测点，而不是跳过。
5. **最终提示词复验**：冻结最终文本后，至少3个新会话连续通过；再在包含已有上下文的会话复验。所有失败尝试留简要记录。这里的三轮是工程放行下限，不是统计可靠性保证。
6. **安装与分发复验**：在已获授权的全局安装后，从普通 `pi` 执行完整路径；另将 ZIP 解压到新目录，仅按学员 README 安装并执行同一提示词。不得暗加开发依赖、隐藏配置或 --no-extensions 绕过组合。未获安装授权时只能交付候选，不宣布全局验收完成。
7. **放行核对**：运行 gate.py 后检查原始证据与实际界面；代码、配置、提示词或组合变化则原结论失效，补测受影响项及最终完整链。收据缺项、失败或证据失配即阻塞。
8. **收尾**：只留核心代码、可复跑入口、最终包、关键截图/终端帧、精简时间线与失败摘要。临时日志、依赖副本与凭据链接在验证进程退出后清理。保留的证据必须足够检查因果，不能只留下一个 PASS 布尔值。

## 三、硬性用例矩阵

以下是新的工程验收目标，**不是当前扩展已经全部达标的声明**。工具等待时1秒内显示动作，至少每2秒刷新可见状态；取消1秒内确认、10秒内回收测试子进程。模型首 token 速度单独测量，不与界面反馈速度混为一谈。

| ID | 操作与必须观察的结果 | 证据来源 |
|---|---|---|
| unit | 正常与非法输入、已知历史故障回归 | 本地确定性测试 |
| combo_tui | 原组合正常调用；监控栏、简洁动作和正文同时可见，无遮挡；量测反馈及刷新时间 | 原生终端帧＋事件 |
| prompt_fresh | 原样粘贴交付提示词，连续3个新会话正确完成；不预种计划，不走隐藏测试命令 | 真实模型＋原生终端＋实际输入哈希 |
| prompt_resume | 同一提示词在有上下文的会话执行，原目标/记录仍可见 | 真实模型＋原生终端 |
| no_events | 首包不回或子进程完全静默：可见等待，默认不晚于120秒截止＋6秒回收，明确失败，不能标成功 | 故障注入＋原生终端＋进程树 |
| stream_drop | 中途断流、缺 finish_reason、截断工具参数：保留已输出正文，明确错误或有限恢复，不执行残缺工具 | 注入＋事件＋终端 |
| heartbeat_stall | 不断输出心跳/日志但业务不推进：预先设置业务截止，不允许心跳无限延长；默认验收上限15分钟 | 注入＋业务状态时间线 |
| cancel_wait | 等待首包时 Esc，及时确认、子进程回收；下一条“你好”正常 | 原生终端＋进程树 |
| cancel_tool | 工具或团队运行中 Esc，同上；不误标完成、不遗留文件占用 | 原生终端＋任务/进程 |
| lifecycle | 连续 /reload 两次、新会话、退出重启；无重复监听/成员/工具；原记录可恢复 | 原生终端＋状态 |
| render | 80/120/160列、深浅背景、中文长文本、折叠展开：不裁切/覆盖，不泄露思考正文/密钥，业务结果不被隐藏 | 真实终端关键帧与视觉检查 |
| repeat_session | 至少3轮连续对话；回复结束静置30秒不按键，正文持续可见；无需 Ctrl+O 才恢复 | 连续终端帧 |
| global_journey | 最终版本全局普通 pi 启动，原始提示词完整走通；不通过 --no-extensions 简化环境 | 安装后真实模型＋终端 |
| clean_install | ZIP 新目录解压，只按发给学员的安装说明运行，同一提示词完成 | 干净安装＋真实模型＋终端 |
| teams_graph（团队） | 依赖死锁、接收人离线、把模型名当成员名、未指定每任务模型：能明确拒绝/阻塞，不无限等 | 原生终端＋任务与收发结果 |
| teams_messages（团队） | 双向消息不仅 sent，还在各接收会话出现；实际模型正确，独立断言通过，子进程退出 | 真实模型＋原生终端＋接收事件 |
| long_run（团队） | ≥15分钟、≥3阶段的真实任务：进度持续可见，目标保留，结果正确，结束无孤儿进程 | 真实模型＋原生终端＋独立验证 |

长任务要为阶段、无事件、业务无进展和整体任务分别设置合理界限。调整界限必须在运行前说明理由；不能失败后仅放大超时、删除失败项或把无响应改名为“正在思考”。耗时使用单调时钟，另记录UTC首尾时间；差异必须解释或保留为未知。

## 四、证据门禁及复用入口

本目录 [gate.py](./gate.py) 是**证据完整性检查器，不是运行 Pi 的自动测试套件**。它阻止空 PASS、fixture 冒充真实模型、RPC 冒充 TUI、改提示词、预置任务替代用户流程、证据缺失/失配、源码漂移和未通过的必测项。它无法凭 JSON 判断日志是否伪造、图像是否真的可读；主控必须检查原始帧/事件，不能把门禁退出0当作验收结论。

需要 Python 3.10+。在测试临时工作区建立收据，核心操作：

```bash
python3 gate.py --init agent-teams > /明确测试目录/acceptance.json
# 一般扩展可用 --init extension；不能为团队扩展降低 profile。
# 实际执行矩阵，填入当前证据和观测值；不要把模板批量改成 PASS。
python3 gate.py /明确测试目录/acceptance.json
python3 -B -m unittest -v test_gate
```

收据要求：

- `runtime`：pi_version、node_version、os、terminal、extensions，写实际运行值。
- `delivery`：source_root、installed_root、extracted_root 指向真实载荷目录；sha256_by_path 是冻结载荷的相对路径→SHA256，全树检查（排除 node_modules、.git、__pycache__、.DS_Store）。加载器、全局设置、模型与项目配置另保留脱敏配置快照/哈希，主控检查漂移；不要保存密钥正文。
- `prompt`：path、sha256，原提示词保存在收据所在目录内。
- `checks`：每个ID独立 status/driver/provider/observations/evidence。evidence 是非空文件的 path/sha256 列表，必须在收据目录内；建议事件摘要＋关键终端帧，不只写结论。
- 真实流程项必须 provider=real、driver=tmux或pty、prompt_sha256与交付文本相同。fresh 的 runs 保留全部尝试，并要求最近3次不同 session_id 连续通过。
- `blockers`：没有阻塞才可为空；历史失败进入 history，保留修复原因和对应重验引用。
- 数字观测字段以 gate.py 为准，与上表量化目标对应；未知值不能填写0代替，未验证不能填写true。

输出 BLOCKED 必须停止完成声明；输出 EVIDENCE_COMPLETE_REVIEW_REQUIRED 仅表示收据完整，仍需核对实际运行、画面和成果后才能作出“冻结范围内验收通过”的结论。
