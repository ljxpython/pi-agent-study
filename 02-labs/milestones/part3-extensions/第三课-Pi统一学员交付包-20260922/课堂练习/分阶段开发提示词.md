# 第三课分阶段开发提示词

按课件顺序使用；这些是交给编程助手的开发任务，不自动注册为Pi模板。使用前把开发指南复制到练习工作目录materials，准备独立样本。

## 3.4 阶段开发提示词

```text
【一、目标：只做E1查询扩展】
从零创建一个最小Extension，注册 /context-usage 命令。
我在Pi原生终端输入命令后，直接看到当前会话的上下文占用估算。

【二、准备：目录、指南与环境】
- 工作目录：~/.pi/agent/lesson3-demo
- 先读取：materials/Pi-Agent-Extensions标准开发指南.md
- 沿用日常全局Pi配置与认证，核对实际Pi/Node版本。
- 参考版本：Pi 0.85.1；版本不同时先核对公开接口。
- 本段已包含本阶段完整需求，不读取整份底栏需求、参考工程或完整版源码。

【三、功能：三种输入，三种处理】
1. 无参数：调用宿主公开接口查询，用通知显示一位小数百分比。
   - 有效0：显示0.0%。
   - 结果缺失、null或非有限数：显示“上下文：待更新”。
   - 数据必须是当前占用，不能用累计token代替。
2. 有不支持的参数：只显示用法，不继续查询。
3. 非TUI模式：安全跳过。

【四、实现：创建什么，保留什么】
先用中文简要说明接口依据和验证方法，然后直接开发，不只给方案，
不等待重复确认。只使用读取、编辑与必要命令，不调用待办、记忆等无关工具。

创建：
- 扩展入口：extensions/context-panel.ts
- 必要的工程配置、锁文件、检查脚本和README

保留：
- samples/project-notes.md
- ~/.pi/agent/prompts/project-map.md
- 日常认证、模型设置、会话及现有其他扩展

加载方式：
pi -e ./extensions/context-panel.ts
只使用这一入口，不创建自动发现桥接，不安装包。

本阶段不做：
- 查询运行时不调用模型、不修改文件。
- 不替换底栏，不增加进度条、开关、持久化或模型工具。

【五、验证与交付：检查后停止】
开发助手先执行：
- 类型检查。
- 针对性测试：正常值、0、未知、非法参数、非TUI。
- 模拟测试只证明分支，不能当作真实终端结果。

开发完成后，给出新终端启动命令，并列出以下输入的验证步骤与预期结果：
1. /project-map samples/project-notes.md
2. /context-usage
3. /context-usage wrong

真实终端验证由当前会话之外的测试者执行：
- 本轮不嵌套启动Pi，不编写固定sleep等待的交互脚本。
- 未实际执行的项目标为“待验证”，不用模拟结果冒充。

将源码入口、加载方式、实际验证和未测项写入README。
完成E1后停止：不增加底栏、不保存偏好、不打包。
```

## 4.3 阶段开发提示词

```text
【一、目标：把查询扩展改为终端底栏】
- 在现有项目上完成E2，不重建工程。
- 移除 /context-usage，新增 /context-panel；暂不保存偏好、不打包。

【二、准备：目录、指南与修改范围】
1. 工作目录：~/.pi/agent/lesson3-demo。
2. 读取 materials/Pi-Agent-Extensions标准开发指南.md，重点参考5.3、5.4、4.5及6.2节。
3. 读取 extensions/context-panel.ts 和README，确认E1前置实现；缺失则停止说明。
4. 使用日常全局Pi配置与认证，核对实际Pi/Node版本，以Pi 0.85.1为参考；版本不同时先核对公开接口。
5. 不读取整份底栏需求、参考工程或完整版源码。保留 samples/project-notes.md 与 ~/.pi/agent/prompts/project-map.md，不修改认证、模型设置、会话或无关扩展。

【三、显示：位置、数据和格式】
- 仅在TUI模式使用公开setFooter接口；单行显示“上下文”、十格进度条和一位小数百分比。
- 读取当前会话上下文估算；缺失、null或非有限数显示“上下文：待更新”，有效0显示0.0%。不使用累计Token，不伪造读数。
- 在README说明固定取整规则，格数限制0—10；超范围值明确降级，不能冒充正常数据。
- 使用主题语义色、可见宽度与裁剪工具；支持中文及60/80/120列。极窄时优先保留标签和数值，必要时省略条形，不越界。

【四、操作：开关、更新与清理】
- on开启，off关闭，toggle及无参数反转；非法参数只提示用法，不改变状态；重复on/off不叠加组件、不报错。
- 本阶段开关只保存在当前进程；每次启动默认开启，不读写偏好文件。
- off恢复Pi原生底栏，不恢复第三方底栏、不取消模型任务、不清空对话。
- 回复结束后无需按键即可更新；换模型、压缩、新建或切换会话后，读取当前数据，不残留旧值。
- render只生成显示内容，不写文件、不请求模型、不重复注册事件。
- 关闭时释放组件创建的订阅与定时器，保留再次开启所需的命令入口；重载、退出按宿主生命周期清理资源。
- 若发现其他底栏冲突，先定位来源并报告停用与恢复步骤；不擅自改无关配置或删除扩展。

【五、验证与交付：明确做过什么】
1. 继续通过 pi -e ./extensions/context-panel.ts 加载，不安装、不建立第二个入口。
2. 先完成类型检查及数值、未知态、取整、参数和宽度边界测试。
3. 使用可用终端测试工具验证真实Pi：模板回复、无按键更新、on/off/toggle/无参数/非法参数、重启默认开启、窄屏、reload与取消恢复。
4. 不从当前Pi对话内启动无法交互退出的嵌套Pi。若当前环境无法独立驱动终端，交付外部终端的逐步输入与预期结果，将该项标记未测，不用固定等待或伪结果替代。
5. 在README记录修改文件、使用方法、实际结果和未测项。完成E2后停止，不实现持久化、不打包。
```

## 5.2 阶段开发提示词

```text
【一、目标：只增加开关偏好的跨窗口延续】
- 基于已完成的E2代码，新增持久化及失败恢复。
- 保留底栏显示、数据更新和命令行为，不重做界面，不打包。

【二、准备：目录、指南与修改范围】
1. 工作目录：~/.pi/agent/lesson3-demo。
2. 读取 materials/Pi-Agent-Extensions标准开发指南.md，重点参考4.4、4.5、5.4及6.2节。
3. 读取 extensions/context-panel.ts 与README；缺少E2前置实现则停止说明。
4. 使用日常全局Pi配置与认证，核对实际Pi/Node版本，以Pi 0.85.1为参考；版本不同时先核对公开接口。
5. 不读取整份底栏需求、参考工程或完整版源码。保留 samples/project-notes.md 与 ~/.pi/agent/prompts/project-map.md，不修改认证、模型设置、会话或无关扩展。

【三、状态：保存什么，何时读取】
- 仅保存底栏显示偏好；不保存上下文数字，不改变模型、思考程度或认证。
- 通过公开接口确定Pi用户配置目录；本课默认全局环境下，文件为 ~/.pi/agent/lesson3-context-panel/state.json，记录格式版本和布尔值enabled。不写入包目录或会话JSONL。
- 首次无记录默认开启。每次明确的on/off/toggle（含无参数）成功提交后，成为后续会话和窗口的默认选择；非法参数不改状态、不写文件。
- 新建/切换会话、reload、重启、新窗口读取最新成功保存值；退出不回写旧缓存。
- 其他已打开窗口不要求实时跟随，但下一次开关操作或加载边界必须读取最新值。toggle以共享记录为起点，不以旧窗口缓存为起点。

【四、保存：并发和失败规则】
- 跨进程串行保护“读取最新值—计算新值—提交”的完整过程；成功写入使用同目录临时文件和原子替换，不能只保护最后一次写文件。
- 说明等待上限、失败反馈和锁资源释放；引入第三方库时声明真实运行依赖。
- 保存成功后再更新本窗口显示；写入失败明确提示未保存，保留操作前显示，不宣称成功。
- 损坏记录或不合法字段：提示问题，采用明确的临时开启状态，不静默覆盖原文件；明确恢复步骤。
- 保留E2的有效0/未知区分、单行布局、刷新、宽度、清理与非TUI边界；最终只保留 /context-panel。

【五、验证与交付：正常、并发、失败分别检查】
1. 继续通过 pi -e ./extensions/context-panel.ts 加载，不安装、不打包。
2. 先完成存储与渲染测试。故障仅在 tests/runtime-fixtures 内注入；不破坏日常偏好、认证或配置目录权限。
3. 使用可用终端测试工具验证：A off保存成功→新B关闭→B on保存成功→A退出→新C开启；同时核对各窗口数据属于自己的会话。
4. 分别验证旧会话恢复、reload、重启、连续toggle、模板真实回复和Esc取消后恢复；并发测试核对两次成功toggle不会丢失一次反转。
5. 不从当前Pi对话内启动无法交互退出的嵌套Pi。若无法独立驱动真实终端，交付外部终端的输入与预期结果，标记未测，不冒充通过。
6. README保留实际结果、失败原因、恢复方法与未测项。完成E3后停止。
```

## 6.2 阶段开发提示词

```text
【一、目标：把现有能力交付给另一个项目】
- 包名 pi-context-panel-lesson，版本0.1.0，提供project-map模板和已完成的E3底栏。
- 不新增业务功能，不发布npm，不全局安装，不更换日常Pi认证配置。

【二、准备：指南、目录与前置结果】
1. 开发目录：~/.pi/agent/lesson3-demo。
2. 读取 materials/Pi-Agent-Package标准打包指南.md、现有代码、package.json和README；重点核对资源发现、实际载荷、依赖与本地安装规则。
3. 以Pi 0.85.1为参考，核对实际版本与已有验证结果；关键功能失败或未测时先说明，不把它标成可交付成品。
4. 新消费目录固定为 ~/.pi/agent/lesson3-consumer；已存在时先读取状态，不覆盖旧项目，不重复已完成的步骤。

【三、组织：资源、依赖与说明】
- 将 ~/.pi/agent/prompts/project-map.md 复制到开发目录 prompts/project-map.md，核对字节一致。
- files收录扩展入口、实际导入模块、prompts及README；pi.extensions、pi.prompts明确声明对应入口。辅助模块不作为独立扩展注册。
- 按目标版本规则声明实际导入的核心peer；测试和类型工具放开发依赖，第三方运行库放运行依赖。依赖分类变更后同步锁文件。
- 不收录materials、hold、tests、项目samples、.pi、认证、会话、偏好、node_modules或开发日志；核对实际附带代码及资源的许可与来源说明。
- README分开写源码开发和使用者安装，列清版本、资源、依赖、启动、调用、偏好路径及移除方法。

【四、生成：检查真实归档】
1. 先阅读package scripts，再执行实际项目需要的检查。
2. 运行 npm pack --dry-run --json，核对清单后运行 npm pack --json。
3. 记录真实tgz文件名和SHA-256，检查实际归档含模板、入口、引用模块与README，且不含排除项。
4. 仅从本次归档解压到消费目录 vendor/，使用 vendor/package；不借用作者源码目录或其node_modules。

【五、安装：排除旧副本，再真实调用】
1. 归档核对后退出本次课堂Pi进程。将全局原模板暂存到开发目录 hold/project-map.md；同名暂存存在则停止核对，不覆盖。安装和移除验证期间，全局原模板路径保持不存在。
2. 消费目录中创建 samples/project-notes.md：项目名“Markdown标题练习”，用途“提取Markdown标题”，入口与验证均尚未确定。已有文件不覆盖。
3. 按解压包README准备真实运行依赖。在消费目录执行 pi install -l ./vendor/package，核对登记和实际资源来源。
4. 沿用默认全局 ~/.pi/agent；不设置独立PI_CODING_AGENT_DIR、不复制认证。按真实情况核对项目信任和底栏冲突，只处理已确认的课堂资源。
5. 普通 pi 启动，不能用-e或--no-extensions代替自动发现验证。发送 /project-map samples/project-notes.md，应回答新的Markdown标题项目。
6. 核对底栏开关、当前数据、偏好延续和取消后继续使用。无法驱动真实终端时交付具体步骤并标记未测，不用嵌套失控Pi或伪结果代替。

【六、移除与交付：保留恢复路径】
1. 退出Pi，在消费目录执行 pi remove -l ./vendor/package，再普通启动，确认本包的模板与底栏命令不再加载；保留项目资料和偏好。
2. 确认移除结果后退出Pi，再按需恢复暂存的全局模板；原目标已存在则停止，不覆盖。
3. 缺模块等反例只在独立副本测试，不破坏正式产物或日常配置。
4. 保留源码、实际归档、README与关键结果；说明已测、失败和未测项。不要自动删除测试目录或用户数据。
```
