# 第三课：最小上下文底栏开发需求

本需求与两份通用指南配合使用，目标是从空目录创建一个可在Pi终端使用的Extension，再打包供另一个项目安装。它是开发与验收输入，不是已实现功能说明。

## 1. 输入、范围与环境

先读配套的[Extensions指南](../开发指南/Pi-Agent-Extensions标准开发指南.md)，打包阶段再读[Package指南](../开发指南/Pi-Agent-Package标准打包指南.md)。目标基线Pi 0.85.1；执行时记录实际Pi/Node/系统/终端/模型版本，版本不同先核对所需公开接口。

工作区为`~/.pi/agent/lesson3-demo/`；消费项目为`~/.pi/agent/lesson3-consumer/`；始终沿用默认全局用户配置`~/.pi/agent`，真实Pi启动前执行`unset PI_CODING_AGENT_DIR`。模型认证沿用日常配置，不复制认证、不新建课堂配置。全局模板为`~/.pi/agent/prompts/project-map.md`，指南与本需求的执行副本位于工作目录materials。正式资料更新后应同步副本；副本不是独立的新权威源。

允许修改本次新建的工作区、消费项目、上述专属模板和`~/.pi/agent/lesson3-context-panel/state.json`；不修改日常认证、模型设置、会话或无关资源。Package仅登记在消费项目，仍使用全局认证。已有同名文件先检查，不覆盖。接口指南、参考源码与完整版只读，不复制完成版冒充从零开发。不同根目录与故障测试只给存储函数传入工作区tests/runtime-fixtures中的测试路径，不切换Pi配置；不得对整个全局目录制造权限或损坏故障。已有底栏冲突时记录准确来源，只临时停用冲突资源并在结束后恢复。

仅实现当前上下文占用、进度条与显式开关。不新增模型工具、Skill、网络服务、账户额度、自动检查、压缩策略、自动取消模型请求或SDK页面。模板作为独立资源先行制作，不依赖本扩展。

## 2. 最终可观察的行为（E3完成后）

| 编号 | 需求 | 通过条件 |
|---|---|---|
| R01 | TUI普通启动后默认启用小底栏 | 单行显示“上下文”、进度条和百分比；未获取数据时显示“上下文：待更新” |
| R02 | 数据来自宿主当前上下文接口 | 百分比来源可追溯；累计token不能代替当前占用；整个结果undefined或percent为null时显示待更新，不报错或清屏；有效零值才显示0% |
| R03 | 进度条10格，数值保留1位小数 | 按明确取整规则绘制；填充限制0—10格，百分比保留真实语义，不伪造实时精度 |
| R04 | `/context-panel on`、`off`、`toggle`；无参数等于toggle | on/off幂等；未知参数显示帮助且不改变状态；off恢复原生底栏 |
| R05 | 开关为同一Pi用户配置范围内共享的持久偏好 | 第一次无记录时默认开启；新建/切换会话、reload、重启及新窗口均读取最近一次成功保存的明确开关操作；旧会话/窗口不得回写覆盖新偏好；上下文数据仍属于当前会话 |
| R06 | 数据变化后主动刷新 | 一轮真实回复结束后无须按键即可看到有效状态；换模型、压缩、新建/切换会话后不滞留旧数据；宿主暂时未知时允许待更新 |
| R07 | 保持终端可读可操作 | 60/80/120列、深浅主题、中文内容下不越界、不遮挡输入、不丢回答；使用主题语义色与宽度工具 |
| R08 | 正确释放资源 | off、reload、退出释放本扩展创建的监听和定时器；重复操作没有重复底栏与后台任务 |
| R09 | 宿主与组合边界明确 | 非TUI安全跳过；人工停用另一底栏后再启用本底栏，保留无冲突扩展；不实现自动检测或仲裁；off只恢复原生底栏，README说明被替换信息 |
| R10 | 新目录安装后可用 | 从实际tgz解压得到包，项目级安装，普通pi启动，不依赖开发目录或显式-e；移除后新进程恢复原生效果 |

底栏布局为本课的最小展示，不承诺保留原生底栏所有信息。未知值、0%、25%、100%及异常数值可用构造数据验证纯渲染，必须标记为测试；真实画面还须实际模型对话验证。进度条表示上下文占用，不表示任务完成百分比。

开关仅指自定义底栏是否显示：on接管底栏，off恢复Pi原生底栏，toggle反转最近保存的共享状态；不停止模型，不清空上下文，不改变Token统计、模型选择、思考程度或压缩配置。重复on/off不叠加组件或报错，但仍代表一次明确的用户偏好操作。

用户已确认状态延续规则：同一Pi用户配置目录内，最后一次成功提交的开关操作成为后续会话/窗口的默认状态。首次没有记录时才默认开启，之后新建/切换会话、reload和重启均读取保存值，不从旧会话日志恢复这个偏好。不同配置目录相互独立；不要求跨电脑同步，也不要求已打开的其他窗口实时跟随。其他窗口下一次执行开关命令或发生上述加载边界时读取最新值。

通过目标版本公开接口获取当前Pi用户配置目录，不硬编码作者路径。本课专属偏好写入默认配置目录下的`lesson3-context-panel/state.json`，即`~/.pi/agent/lesson3-context-panel/state.json`。只修改这个本课状态，不改认证、模型设置或其他扩展数据。包安装目录和会话JSONL不是偏好存储位置；不将偏好文件打入Package。至少记录数据格式版本和enabled。并发读改写必须串行并原子替换，toggle必须在同一受保护操作中读取最新值后反转；近同时操作以成功提交顺序为准，不用窗口创建时间或系统时钟推定先后。启动、切会话、reload、退出只读取/清理，不把旧缓存写回。写入失败要明确提示，不能宣称已保存；损坏记录应提示并采用明确的临时默认显示，不静默覆盖原文件。

R05验证：A窗口off后新建B应关闭；B执行on后，A退出再新建C应开启；切换到旧会话、reload和进程重启仍沿用on；不同测试存储根不继承的性质通过存储层测试检查，不以此冒充另一套Pi配置的运行验收。另测两个窗口顺序toggle、并发更新、写入失败和损坏文件；核对偏好文件与画面一致且不泄漏会话数据。上述为确定的验收要求，尚未实现或实测。

## 3. 实现与交付

开发助手自行核对公开接口，优先从单文件扩展起步，必要时拆纯计算模块；不要求预设架构。建议入口为 `extensions/context-panel.ts`，包名 `pi-context-panel-lesson`，版本 `0.1.0`。固定模板输入存放于 `samples/project-notes.md`，不得在其中追加开发说明或验收日志。根目录README专用于扩展说明和验证记录。提供类型检查、必要测试、README与锁文件；README列数据来源、事件刷新、状态寿命、冲突、启动和恢复。

Package包含Extension、确实被导入的模块和已验证的 `prompts/project-map.md`；不包含整个.pi、用户配置、模型凭据、会话或node_modules。模板从全局`~/.pi/agent/prompts/project-map.md` 转入分发目录时比较字节/哈希；消费项目不再放第二份同名模板。必须逐项核对files包含prompts、实际tgz含prompts/project-map.md、pi.prompts明确声明该模板，安装后原斜杠入口可调用。samples是消费项目的独立测试输入，不纳入能力包；不得借包内样本替代当前项目资料。按指南处理核心peer与开发依赖。先检查真实归档文件，计算SHA256，再将全局原模板暂存到工作区hold；确认全局原路径不存在后才安装验证，以排除全局副本兜底。materials、hold、测试文件和偏好不得入包。完成移除验证后再按需恢复全局模板。不发布npm，不做全局安装。

## 4. 执行阶段与验收

M0：检查输入、确认全局配置与本课专用工作目录和实际版本，列接口映射及未知项；只对改变结果的缺口提问。

M1：先建立微型项目资料与纯模板，创建完成后启动Pi，真正发送 `/project-map samples/project-notes.md`；沿用全局模板，若其他项目资源触发信任提示则审阅其来源；具体资料和模板需求见[分阶段开发提示词](./分阶段开发提示词.md)。

M2分为E1、E2、E3三个明确停点，由课件各章的请求依次授权。每个阶段做完对应验证后停止，不提前实现后续阶段。R01—R09为最终目标，不能用它强制E1、E2提前完成持久化。

| 阶段 | 章节与当前行为 | 本轮验证 | 尚不实现 |
|---|---|---|---|
| E1 按需查询 | 第三章；同一入口文件注册/context-usage，不带参数查询当前上下文估算，通过通知反馈 | 参数、未知与有效0、真实当前数据、查询不请求模型、不改变原生底栏 | footer、开关、偏好文件 |
| E2 终端显示 | 第四章；在原入口移除/context-usage，换为/context-panel on/off/toggle及无参数切换；进程内状态，重启默认on | R01—R04、R06—R09的本阶段显示与恢复；README明确临时状态 | R05持久偏好，不得提示已保存 |
| E3 状态延续 | 第五章；保持显示合同，新增R05共享偏好与失败恢复；写入失败保留原显示 | R01—R09完整回归，重点跨窗口、并发、损坏、恢复 | 打包由M3单独授权 |

开发阶段统一只用`pi -e ./extensions/context-panel.ts`，不创建`.pi/extensions`桥接、不登记开发包。配套参考工程存在自己的自动发现桥接，不能同时-e；参考源码不供从零实验助手读取。最终Package中只保留/context-panel，不保留E1查询命令。中间版本需分别记录真实输入与图像；最终参考实现的截图不能证明E1或E2已验收。

M3：按打包指南制作归档，在新消费目录只按README安装，验证R10并重新验证模板和底栏。运行时与包身份必须对应。

M4：停用课堂版后演示已有完整版；完整版资产与本次课堂版分开验收，不能同时接管footer。独立接手测试只允许指南、需求、版本资料及必要测试输入，接手者不得看完成版。

所有阶段保留代表输入、预期、实际、版本/哈希、终端关键帧、失败原因和未测项。记录在项目README的验收表，避免并行报告。项目内执行遵循[Pi扩展验收规范](../验证工具/验收规范.md)，逐项说明适用性，不能静默跳过完整组合和真实模型测试。

遇到卡顿必须保留失败并定位模板展开、Provider、渲染或生命周期原因，再用原输入复测。模板首个内容/工具动作目标30秒内，简短完整回复目标60秒内；超过即记体验失败，最迟90秒Esc取消，允许提前取消，取消后发送“你好”检查基础恢复，再重发原斜杠请求验证任务恢复。本扩展只显示数据，不提供自动超时保护。外部鉴权/服务阻塞应明确记录，不反复空转或改成假数据通过。

本练习已明确采用日常全局配置与消费项目级安装。全局正常启动、真实模型和既有资源组合需按验收规范实测；当前文档更新不代表这些项目通过。先记录实际扩展集合、底栏唯一所有者、加载来源及原输入，关键失败或未测保持未通过。本轮只改文档，不实施全局资源、偏好或安装记录修改。
