# 核心代码逻辑：从会话数据到监控栏

阅读顺序：`extensions/index.ts` → `src/monitor.ts` → `src/usage.ts` → `src/quota.ts` → `tests/`。本说明对应包内Pi 0.85.1实现，不是新增监控服务或压缩算法。

## 1. 一条运行链

```text
Pi加载 extensions/index.ts
  → registerMonitor(pi) 注册命令和事件
  → session_start 取得当前ExtensionContext
  → 仅在TUI模式安装 setFooter()
  → render() 读取当前模型、上下文与会话用量
  → monitorLines() 生成有颜色、受宽度约束的文本行
  → Pi负责把这些行绘制到终端
```

这是终端组件，不是网页。CSS、DOM、浏览器事件不参与运行；预览图仅帮助理解布局。

## 2. 模块如何分工

| 模块/函数 | 输入 | 输出/职责 |
|---|---|---|
| `registerMonitor` | Pi扩展API | 注册事件、命令和快捷键，管理底栏生命周期 |
| `monitorLines` | 宽度、MonitorData、可用行数 | ANSI文本行；不请求模型、不读取文件 |
| `quotaColor` | 已用百分比 | 80%前固定绿色，之后按区间线性插值 |
| `usageTotals` | 当前会话文件entries | input/output/cacheRead/cacheWrite之和 |
| `parseQuota` | JSONL文本、当前时间 | 明确七天窗口的最新有效记录或过期状态 |
| `readWeeklyQuota` | 本地会话目录 | 有界扫描、读取尾部、保留较新快照 |

`monitor.ts`只依赖独立的`usage.ts`和`quota.ts`，没有导入工单业务、讲师目录或网页后台。入口使用相对路径，因此整个文件夹可迁移。

## 3. 默认与展开的数据口径

| 显示位置 | 数据源 | 关键边界 |
|---|---|---|
| 模型 | `ctx.model.id` | 不写死讲师模型名 |
| 思考 | `pi.getThinkingLevel()` | 表示Pi档位，不保证上游内部推理行为 |
| 上下文 | `ctx.getContextUsage()` | unknown/null不当作0；模型窗口动态读取 |
| 最近回复 | 最新assistant消息的usage | 默认可见；不同于整轮所有工具调用用量之和 |
| 本次缓存 | 同一条assistant消息的cacheRead/cacheWrite | 与最近回复同一范围，统一青色 |
| 会话累计 | `usageTotals(getEntries())` | 包括当前文件的分支和摘要；不是上下文占用 |
| 自动压缩 | 有效settings与模型窗口 | 只显示开关、触发比例和事件状态 |
| Codex周额度 | 本地Codex日志快照 | 只有订阅接入显示，与其他API额度无关 |

## 4. 为什么布局逻辑与运行逻辑分开

`MonitorData`是渲染输入。测试可以直接提供构造数据验证：

1. 同样的数据在60、80、120列下是否越界；
2. 收起时最近输入/输出是否可见；
3. 展开后是否重复显示最近回复；
4. 不同模型接入是否正确隐藏周额度；
5. 80%、85%、95%的额度颜色是否连续变化。

`monitorLines()`生成完整宽度的深色背景，并在每行末尾重置ANSI状态，防止背景“染到”后面的输入区域。中文宽度使用`visibleWidth()`计算，不能用字符串长度代替。截断文本后补回背景色，避免浅色终端里出现白块。

上下文进度条最多28列；使用八分之一字符表现低占比，避免2.5%被四舍五入成完全空条。它一直是绿色。周额度采用单一随占比变化的颜色，数字和条形同步变化，不是每次突然切换整套主题。

宽屏把最近回复与核心指标并排；空间不够时换行。展开区只保留缓存和会话累计，底部只留自动压缩状态。小终端优先减少空白行。

## 5. 事件与资源回收

- `session_start`：安装底栏，重置本次压缩状态。
- `model_select`：更新当前context、重绘，按接入类型决定是否读取额度。
- agent/tool/session相关事件：重绘最新数据。
- `session_before_compact` / `session_compact` / `session_compact_failed`：更新进行中、已完成、取消或失败提示。
- `/monitor`：只切换显示状态，不调用工具、不请求模型。
- `dispose()`：清理定时器与分支监听；`session_shutdown`移除底栏。

后台定时器每5秒触发显示刷新；额度读取最多每30秒一次。`pending`避免并发读取，`generation`阻止旧实例的异步结果在关闭后写回界面。普通非Codex模型不会为了显示监控栏扫描Codex日志。

## 6. 可以动手修改的三个练习

1. **调整进度条长度**：修改上下文条的最大宽度，保留未知值与满格边界测试。
2. **调整额度配色**：修改`quotaColor()`锚点，保证80%前稳定、80%后连续、数字和条形同色。
3. **新增一个真正需要的指标**：先说明它属于最近回复、当前会话还是账号范围，再扩充数据输入与渲染；不要把账户额度从Token累计中推算出来。

每次修改后先运行`npm run check`和`npm test`，再用`npm run preview -- --expanded`看布局，最后运行真实终端检查。不能用构造数据截图代替真实取值、模型请求或课堂全过程通过。

## 7. 保持的边界

本包不修改压缩阈值、不改变输出预算、不调整认证、不写入全局模型配置、不发送日志。设置修改仍由Pi和使用者负责。

原生 `setFooter()` 是单一位置，多个底栏扩展不会自动合并；停用本扩展恢复的是Pi原生底栏。遇到兼容问题先使用临时加载入口排除冲突，再决定如何集成。
